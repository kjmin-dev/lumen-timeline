# Roadmap

Clock and waveform experiments have established the v1 implementation boundaries. The milestones below track delivery of the library and its release gates. [Core architecture and measurement evidence](docs/core-architecture.md#evidence-and-implementation-gates)

The first release should let an application attach a timeline to an existing player, or use the same packages to build a multitrack editor. The [design](docs/design.md) defines the behavior each milestone must preserve.

## Framework support

Provide one wrapper per framework, targeting its **latest stable major**. The JavaScript API and vanilla DOM mount are the reference implementation for all four. Package names in this plan are proposed.

| Wrapper                  | Framework peer               | Target major | Stable release observed on 2026-11-21                      |
| ------------------------ | ---------------------------- | ------------ | ---------------------------------------------------------- |
| `@lumen-timeline/react`  | React and matching React DOM | 19.x         | [React 19.3.1](https://registry.npmjs.org/react/19.3.1)    |
| `@lumen-timeline/svelte` | Svelte                       | 5.x          | [Svelte 5.59.1](https://registry.npmjs.org/svelte/5.59.1)  |
| `@lumen-timeline/solid`  | SolidJS (`solid-js`)         | 2.x          | [SolidJS 2.0.3](https://registry.npmjs.org/solid-js/2.0.3) |
| `@lumen-timeline/vue`    | Vue                          | 3.x          | [Vue 3.5.46](https://registry.npmjs.org/vue/3.5.46)        |

At each wrapper release, resolve the framework's stable npm `latest` tag, run its integration suite and record the tested version. A new stable major becomes the target for the next compatibility update. Publish its peer range after it passes. Pin exact test versions in benchmark reports so readers can reproduce a result.

**Status.** Milestones 1 to 6 are complete. The podcast editor on the [examples page](apps/docs/src/content/docs/examples.mdx) puts two speakers on tracks of their own, overlapping where one answers over the other, with a theme on a music track, chapters as markers and a level control that sets the selected clips' gain. `npm run docs:test` drives it in the built site: both voices are planned and booked across the overlap, the theme plays under the opening at its track's gain, a chapter is renamed in the transcript, a drag on the level is heard as it moves and undone in one step, and a cut through the overlap takes whole words from both speakers. The same test checks that the dubbing studio and the podcast editor import only the packages' public entry points. Projects are now at schema 2, which adds clip gain and records the version of each plugin's payloads; an editor opens schema 1 by migrating a copy, opens a later schema read-only, and keeps payloads whose plugin is absent or newer exactly as written. `packages/core/test/migrate.test.ts` round-trips a schema-1 fixture through editing, saving and reopening against a golden schema-2 file, and the same project through an editor without its plugin. [Plugins and persistence](docs/plugins-and-persistence.md) documents plugins, saving and migrations, and [Attach to an existing player](docs/external-players.md) a timeline that follows a player the page did not build, which `npm run verify:external` checks in three engines. [Plan](docs/plans/first-release.md) The release gates below that need reference hardware remain open: the wired A/V measurement, the 30-minute sync run and the render benchmark's run-to-run variation. React, Svelte, SolidJS and Vue each have a wrapper package that mounts the shared view after client mount, forwards changed options to it through `view.update` without a new mount, hands the host's editor and transport to panels, and selects editor and transport fields for them. `npm run verify:wrappers` builds a minimal production consumer per framework and a vanilla one from the packages' public exports, and runs the wrapper acceptance tests below on each. Five mount, update and unmount rounds, an editor swap and a renderer swap leave no subscription, frame callback, observer or GPU context, also in each framework's development build. A take inspector receives no update during ten seconds of playback. One seek, trim, split, undo and take-change trace ends on the same snapshot, takes, audio spans and hit tests in all five. Each bundle holds only its own framework, and a server render subscribes to nothing. `npm run bench:wrappers` publishes frame work, pointer latency and missed refreshes against vanilla's run-to-run spread, and every wrapper is within it. Each wrapper's peer range starts at the version tested: React 19.3.1, Svelte 5.59.1, SolidJS 2.0.3 and Vue 3.5.46. ## Wrapper acceptance tests

- Mount, update options, unmount and remount in each framework. Count active subscriptions, animation callbacks, audio nodes and GPU contexts. Repeated mounts must release view-owned resources and preserve an editor supplied by the host.
- Play the same project with a fixed viewport and the same selection for ten seconds. A take inspector subscribed only to the selected clip and active take should receive **zero updates**. Framework wrappers should cause **zero additional uploads of static clip geometry** relative to vanilla.
- Replay the same seek, trim, split, undo and take-change commands through all five consumers. Compare project snapshots, selected take IDs, audio boundaries and pointer hit results.
- Use production builds on the same browser, hardware, viewport and backend. Compare p95 frame time, input-to-paint drag latency and missed refreshes over repeated runs. Publish the vanilla baseline and run-to-run variation alongside each wrapper's figures. Investigate regressions outside that variation before release.
- Keep each framework a peer of its own wrapper. A vanilla consumer should load only the JavaScript packages it imports. Importing a wrapper in a server-rendered app must defer browser resources until client mount.
