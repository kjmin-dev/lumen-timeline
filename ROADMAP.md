# Roadmap

Clock and waveform experiments have established the v1 implementation boundaries. The milestones below track delivery of the library and its release gates. [Core architecture and measurement evidence](docs/core-architecture.md#evidence-and-implementation-gates)

The first release should let an application attach a timeline to an existing player, or use the same packages to build a multitrack editor. The [design](docs/design.md) defines the behavior each milestone must preserve.

## Framework support

Provide one wrapper per framework, targeting its **latest stable major**. The JavaScript API and vanilla DOM mount are the reference implementation for all four. Package names in this plan are proposed.

| Wrapper                  | Framework peer               | Target major | Stable release observed on 2026-11-21                      |
| ------------------------ | ---------------------------- | ------------ | ---------------------------------------------------------- |
| `@lumen-timeline/react`  | React and matching React DOM | 19.x         | [React 19.3.1](https://registry.npmjs.org/react/19.3.1)    |
| `@lumen-timeline/svelte` | Svelte                       | 5.x          | [Svelte 5.59.1](https://registry.npmjs.org/svelte/5.59.1)  |
| `@lumen-timeline/solid`  | SolidJS (`solid-js`)         | 2.x          | [SolidJS 2.0.3](https://registry.npmjs.org/solid-js/2.0.3) |
| `@lumen-timeline/vue`    | Vue                          | 3.x          | [Vue 3.5.46](https://registry.npmjs.org/vue/3.5.46)        |

At each wrapper release, resolve the framework's stable npm `latest` tag, run its integration suite and record the tested version. A new stable major becomes the target for the next compatibility update. Publish its peer range after it passes. Pin exact test versions in benchmark reports so readers can reproduce a result.

**Status.** Milestones 1 to 4 are complete. The timeline draws one CPU layout through WebGL2 by default, WebGPU on request or Canvas 2D, and recovers from a lost device. `npm run verify:renderers` runs the same geometry, hit-test and edit fixtures on all three backends and loses the device during playback and a drag, and `npm run verify:scale` checks that work follows the view on a 20,000-clip project. Waveform tiles come from a worker with the Rust SIMD kernel, which `npm run verify:peaks` checks against JS bit for bit. `npm run bench:render` publishes frame work, missed refreshes, memory and cold and warm seek latency for the benchmark project; on an Apple M1 every backend met the rendering target. [Plan](docs/plans/scale-rendering.md) · [Benchmark](docs/vanilla-timeline.md#benchmark) `npm run verify:studio` walks milestone 3's exit criteria: it edits a line, generates, auditions and applies a take, splits the line, regenerates only the right half, undoes and reopens. It then checks the left clip's samples and candidates, and reproduces a stale generation result that leaves the current line intact. The example also carries the milestone's other deliverables: a track per speaker, a bilingual list of placed lines with line play (`npm run verify:lines`) and a reference stem drawn as a waveform (`npm run verify:waveforms`). CI runs all three traces. The [candidate takes plan](docs/plans/clip-takes.md) records the take work. The [clock verification](docs/clock-and-wasm.md) probes cover milestone 1. `npm run verify:milestone` walks milestone 2's exit criteria in one browser session, and CI runs it. It edits the video workspace with the pointer and the keyboard, saves and reopens the project, replays the same commands headlessly to the same snapshot, and plays an audio-only project through silence to a marker after its last clip. [Acceptance plan](docs/plans/milestone-2-closeout.md)

The vanilla Canvas 2D example connects selection, seeking, pointer and keyboard edits, and project reload to the playback and history engines. The video and audio-only hosts share a voice scheduler and the same timeline view. Saved markers can be added at the playhead, stepped through from the keyboard, renamed, removed, undone and reopened, and they extend an audio-only sequence. Playback reports each marker it crosses, while a seek skips the markers it jumps over. [Marker plan](docs/plans/timeline-markers.md) · [Marker crossings](docs/media-transports.md#marker-crossings)

## Wrapper acceptance tests

- Mount, update options, unmount and remount in each framework. Count active subscriptions, animation callbacks, audio nodes and GPU contexts. Repeated mounts must release view-owned resources and preserve an editor supplied by the host.
- Play the same project with a fixed viewport and the same selection for ten seconds. A take inspector subscribed only to the selected clip and active take should receive **zero updates**. Framework wrappers should cause **zero additional uploads of static clip geometry** relative to vanilla.
- Replay the same seek, trim, split, undo and take-change commands through all five consumers. Compare project snapshots, selected take IDs, audio boundaries and pointer hit results.
- Use production builds on the same browser, hardware, viewport and backend. Compare p95 frame time, input-to-paint drag latency and missed refreshes over repeated runs. Publish the vanilla baseline and run-to-run variation alongside each wrapper's figures. Investigate regressions outside that variation before release.
- Keep each framework a peer of its own wrapper. A vanilla consumer should load only the JavaScript packages it imports. Importing a wrapper in a server-rendered app must defer browser resources until client mount.

## Engine acceptance targets

These are proposed targets for implementation and measurement.

| Area               | Fixture                                                                                                                                            | Target                                                                                                                                                        |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Edit precision     | 1,000 deterministic trim, split and move operations with undo/redo                                                                                 | No unintended duration changes, duplicate boundary samples or regenerated IDs on redo.                                                                        |
| Audio boundaries   | Offline impulse render at the source sample rate, unity gain and 1× speed                                                                          | Onset within one sample of the expected source index.                                                                                                         |
| A/V sync           | Thirty minutes of numbered frames, flashes and beeps at 30 fps, measured from captured output                                                      | Foreground playback p95 absolute A/V offset at most one frame on the reference wired setup. Report drift, device and output path.                             |
| Seek races         | 100 seeks mixed with stalls, looping and take changes                                                                                              | After the device has drained previously submitted samples, only audio from the current playback generation is audible.                                        |
| Timeline rendering | 60 Hz desktop, 1440 × 900 CSS pixels, DPR 2, two hours, 40 tracks, 20,000 clips, 12 visible rows, 1080p video and eight simultaneous audio sources | During a 60-second pan, zoom and drag trace on GPU, p95 main-thread frame work at most 8 ms and missed refreshes at most 1%. Record the hardware and browser. |
| Recovery and input | GPU loss, unavailable workers, missing assets, keyboard and screen-reader editing, IME composition                                                 | Restore the view at the same position and selection. Preserve edits and asset placement. Text composition must not trigger a timeline command.                |
